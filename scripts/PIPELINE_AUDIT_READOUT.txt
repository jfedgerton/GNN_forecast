1.2  network_construction.py — Distance Residualization
--------------------------------------------------------------------

FILE: src/gnn_forecast/network_construction.py

HAVERSINE (lines 10-15):
  Standard great-circle distance in km. Uses Earth radius = 6371 km.
  This is the real haversine formula, not an approximation.

CAPITAL DISTANCE MATRIX (lines 18-28):
  For every ordered pair (i, j) where i != j, computes haversine
  distance using cap_lat, cap_lon columns from nodes.csv.
  Returns DataFrame with columns: source_ccode, target_ccode,
  capital_distance_km.

  FLAG: This is O(N^2). For 200+ countries it computes ~40,000 pairs.
  FLAG: Requires nodes.csv to have cap_lat and cap_lon columns.

RESIDUALIZATION (lines 31-39):
  residualize_ties_against_distance():
    1. Left-joins edges with distance matrix on (source_ccode, target_ccode)
    2. Runs OLS: tie ~ intercept + capital_distance_km
    3. Adds pred_tie = predicted value, tie_resid = tie - pred_tie

  FLAG: This is a SIMPLE LINEAR REGRESSION, not fixed effects.
        The R script does fixed effects; this Python version is simpler.
  FLAG: If the merge produces NaN distances (missing pair), the
        regression will propagate NaN. Check your nodes.csv coordinates.

1.3  interventions.py — Embeddedness & Edge Interventions
--------------------------------------------------------------------

FILE: src/gnn_forecast/interventions.py

EMBEDDEDNESS SCORE (lines 30-36):
  embeddedness_score(emb, idx):
    1. Take row idx from embedding matrix
    2. L2-normalize ALL rows (with epsilon 1e-8 for stability)
    3. L2-normalize the focal row
    4. Compute cosine similarity: all_norm @ v_norm
    5. Return the MEAN cosine similarity across ALL nodes (including self)

  FLAG: The score INCLUDES the self-similarity term (cos(v, v) = 1.0).
        This inflates absolute scores but is consistent across comparisons.
  FLAG: Score range is [-1, 1] in theory. In practice with non-negative
        adjacency-based embeddings, it will be in [0, 1].
  FLAG: This measures how "central" or "typical" a node's embedding is
        relative to the whole system. It is NOT a standard network
        centrality measure.

EDGE TOGGLE (lines 39-73):
  simulate_edge_toggle():
    For each partner:
    1. Copy adjacency matrix
    2. If edge exists: zero it out (remove). If not: set to 1 (add).
    3. Compute ONE-HOP message passing: emb2 = (adj2 @ emb) / degree
    4. Compute embeddedness_score on the MODIFIED embedding
    5. Delta = new_score - baseline_score

  FLAG: The intervention modifies the ADJACENCY, then re-derives
        embeddings via one-hop aggregation. It does NOT retrain any model.
  FLAG: This is a PROXY for the true effect. The one-hop pass is a
        simplified GNN step, not a full re-embedding.
  FLAG: adj2 is symmetric — both (i,j) and (j,i) are toggled.

RANDOM MULTI-EDGE DELETION (lines 80-136):
  simulate_random_multi_edge_deletion():
    For each k in k_values:
      If focal node degree >= k:
        For n_sims simulations:
          1. Sample k neighbours uniformly without replacement
          2. Zero out those edges (both directions)
          3. One-hop message pass on modified adjacency
          4. Record embeddedness delta

  FLAG: Uses numpy RNG with explicit seed for reproducibility.
  FLAG: k values that exceed the focal node's degree are SKIPPED, not
        errored. This means output may have fewer rows than expected.

1.4  forecast.py — Autoregressive Forecaster
--------------------------------------------------------------------

FILE: src/gnn_forecast/forecast.py

MODEL ARCHITECTURE (lines 10-21):
  EmbeddingAR:
    - GRU: input_size=emb_dim, hidden_size=hidden_dim, batch_first=True
    - Linear head: hidden_dim -> emb_dim
    - Forward: takes [num_nodes, seq_len, emb_dim], returns [num_nodes, emb_dim]
      (the prediction for the NEXT time step)

  FLAG: This is a SHARED GRU across all nodes. Each node's sequence is
        processed independently but with the same weights. There is NO
        inter-node communication during forecasting.

ROLLOUT (lines 37-48):
  rollout_embeddings():
    1. Clone history tensor
    2. For each step: predict next embedding, append to sequence,
       drop oldest time step (sliding window)
    3. Return all predictions stacked: [num_nodes, steps, emb_dim]

  FLAG: Autoregressive rollout compounds errors. By step 25, predictions
        are far from reality. This is a SCENARIO PROJECTION, not a
        point prediction (as noted in CLAUDE.md).
  FLAG: The sliding window means the model always sees seq_len time
        steps, regardless of how far into the future it is forecasting.

DECODE EDGES (lines 24-27):
  Inner product decoder: score = emb @ emb.T
  Threshold at 0.0 to produce binary adjacency.

  FLAG: This decoder assumes that similar embeddings = likely edge.
        With row-normalised adjacency embeddings, this is reasonable
        but not calibrated.

1.5  master.py — Pipeline Orchestration
--------------------------------------------------------------------

FILE: scripts/master.py

ADJACENCY CONSTRUCTION (lines 113-128):
  build_adjacency():
    - Iterates edge DataFrames, sets adj[i,j] = max(current, tie_weight)
    - Symmetrizes: adj[j,i] = adj[i,j]
    - Zeros diagonal
    - If layer=None, aggregates ALL layers (max weight wins)

  FLAG: The "max" aggregation means that if alliance=1 and trade=0.5
        for the same pair, the aggregate weight is 1.0, not 1.5.
        This is a design choice, not a bug.

ADJACENCY-TO-EMBEDDING (lines 131-135):
  adjacency_to_embeddings():
    - Row-normalise adjacency: each row sums to 1.0 (or 0 if isolate)
    - This is equivalent to a 1-hop mean-aggregation GNN with identity
      features (each node's embedding = average of its neighbours'
      adjacency rows)

  FLAG: Isolate nodes (degree 0) get all-zero embeddings due to
        clamp(min=1.0) preventing division by zero. Their embeddedness
        score will be 0.0 (cosine with zero vector = 0).

EMBEDDING HISTORY FOR FORECAST (lines 478-494):
  For each year, build row-normalised adjacency as a "structural embedding".
  If num_nodes > emb_dim: TRUNCATE to first emb_dim columns.
  If num_nodes < emb_dim: ZERO-PAD to emb_dim columns.

  FLAG: Truncation loses information about nodes with index >= emb_dim.
        With full data (~200 countries), default emb_dim=8 means only
        the first 8 columns of the row-normalised adjacency are kept.
        This is a dimensionality reduction, not a principled embedding.

SECTION 4: KNOWN LIMITATIONS & CAVEATS
====================================================================

1. EMBEDDEDNESS IS NOT STANDARD CENTRALITY
   The embeddedness_score function computes mean cosine similarity of
   a node's embedding to all other embeddings. This is a custom metric.
   It correlates with degree but is not identical to betweenness,
   eigenvector centrality, or any standard measure.

2. ONE-HOP PROXY FOR INTERVENTIONS
   Edge toggle interventions re-derive embeddings via a single
   message-passing step (adj @ emb / degree). This is a first-order
   approximation. In a real multi-layer GNN, removing an edge would
   propagate through multiple hops.

3. SELF-SIMILARITY INCLUDED IN EMBEDDEDNESS
   The mean cosine similarity includes cos(v_i, v_i) = 1.0 for the
   focal node. This is a constant offset that doesn't affect rankings
   but inflates absolute scores.

4. AGGREGATE ADJACENCY USES MAX, NOT SUM
   When combining layers, the maximum tie weight across layers is used.
   This means a country with alliance=1, igo=1, trade=1 gets the same
   aggregate weight as one with alliance=1, igo=0, trade=0.

5. AR FORECAST COMPOUNDS ERRORS
   The GRU forecaster is autoregressive: each step feeds on its own
   prediction. By step 25, the signal is largely the model's own
   recurrent dynamics, not the original data. Treat 2026-2050
   projections as scenario explorations.

6. EMBEDDING TRUNCATION
   When num_nodes > emb_dim (default 8), the row-normalised adjacency
   is truncated to the first emb_dim columns. This is a lossy
   projection. The "first 8 columns" correspond to the 8 nodes with
   the lowest ccodes, which may not be the most informative.

7. ROW NORMALIZATION ERASES WEIGHT MAGNITUDE
   The adjacency_to_embeddings() function row-normalises, so each row
   sums to 1.0.  This means layers with the same *topology* but
   different *weights* produce identical embeddings.  For example,
   alliance=1 and igo=3 for the same (i,j) pair contribute equally
   to the row-normalised embedding.  The "aggregate" embeddedness
   therefore differs from per-layer scores only when different layers
   have different *connectivity* (different partners), not different
   weights.  This is a deliberate simplification.

8. FIXTURE DATA IS TINY
   The test fixtures have 3 countries and 2 years. All fixture results
   should be verified against full peacesciencer data for any
   substantive conclusions.

9. DISTANCE RESIDUALIZATION DIFFERS FROM R SCRIPT
   The Python residualization uses simple OLS (tie ~ intercept + distance).
   The R script uses fixed-effects models controlling for node-level
   effects. Results will differ.

SECTION 6: HOW TO VERIFY OUTPUTS ARE NOT HALLUCINATED
====================================================================

1. RUN WITH --summary AND CROSS-CHECK:
   The system summary reports edge counts, density, and degree
   distributions. These can be independently verified:
     - Count rows in edges_*.csv for a given year
     - Compare to n_edges in system_summary.csv
     - density = n_edges / (N*(N-1)/2)

2. SPOT-CHECK EMBEDDEDNESS VALUES:
   For a specific (year, country, layer):
     a. Build the adjacency matrix by hand from the CSV
     b. Row-normalise it
     c. Compute cosine similarity of the focal row to all rows
     d. Take the mean
   This should exactly match embeddedness_over_time.csv.

3. VERIFY EDGE TOGGLE DIRECTION:
   Removing an edge from a well-connected node should DECREASE its
   embeddedness (negative delta). If you see positive deltas for
   removals, investigate — it could indicate the edge was actually
   hurting centrality (rare but possible with adversarial structure).

4. CHECK RANDOM DELETION MONOTONICITY:
   In random_deletion_summary.csv, mean_delta should generally become
   more negative as k increases (removing more edges hurts more).
   Non-monotonicity is possible due to sampling but the trend should
   be clear.

5. REPRODUCE WITH FIXTURES FIRST:
   Run: PYTHONPATH=src python scripts/master.py --summary
   The fixture run has 3 countries and 2 years. Every value can be
   hand-verified. Confirm the flag checks pass before trusting
   full-data results.

6. COMPARE TO embeddedness_analysis.py:
   The standalone embeddedness_analysis.py script uses identical logic
   (same build_adjacency, same adjacency_to_embeddings, same
   embeddedness_score). Running both on the same data should produce
   IDENTICAL embeddedness_over_time.csv and edge_toggle_impacts.csv.
   Any discrepancy indicates a bug.
